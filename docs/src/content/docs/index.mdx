<CardGrid stagger>
	<Card title="Take only what you need" icon="puzzle">
		Each module is its own Go module, so `go get` pulls in only what you use.
		An app that just serves HTTP depends on the core package alone.
	</Card>
	<Card title="Services, not frameworks-in-frameworks" icon="seti:go">
		A service is three methods: `Name`, `Init`, `Close`. The container
		resolves constructors, sorts dependencies, and manages the lifecycle.
	</Card>
	<Card title="Wired by interface" icon="random">
		Modules meet through provider interfaces declared in core, so any of them
		swaps for your own implementation or a test mock.
	</Card>
	<Card title="Fails at startup, not in production" icon="error">
		Unresolved dependencies, malformed services, and handler signature
		mismatches are all rejected before the server accepts traffic.
	</Card>
</CardGrid>
