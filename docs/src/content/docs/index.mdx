## Quickstart

```sh
go get github.com/gasmod/gas
```

<Code code={region(landing, 'app')} lang="go" title="main.go" />

That is a complete Gas app. `Run` starts the server and blocks until the
process receives SIGINT or SIGTERM, then shuts the app down.

## Why Gas

<CardGrid>
	<Card title="Take only what you need" icon="puzzle">
		Each module is its own Go module, so `go get` pulls in only what you use.
		An app that just serves HTTP depends on the core package alone.
	</Card>
	<Card title="Constructor injection" icon="seti:go">
		A service is three methods: `Name`, `Init`, `Close`. The container
		resolves constructor parameters, initializes services in dependency
		order, and closes them in reverse.
	</Card>
	<Card title="Wired by interface" icon="random">
		Modules meet through provider interfaces declared in core, not by
		importing each other. Each module's service sits behind an interface, in
		core or in the module itself (`storage.Provider`, `auth.Authenticator`),
		so any of them swaps for your own implementation or a test mock.
	</Card>
	<Card title="Fails at startup, not in production" icon="error">
		Unresolved dependencies, malformed services, and handler signature
		mismatches are all rejected before the server accepts traffic.
	</Card>
	<Card title="Graceful shutdown" icon="approve-check">
		On shutdown the HTTP server drains in-flight requests within
		`ShutdownTimeout`, 30 seconds by default, and then every active service's
		`Close` runs.
	</Card>
	<Card title="Runtime kill switch" icon="warning">
		`CloseService` tears down one running service: the event subscriptions
		it made with `SubscribeWithOwner` are removed and its routes answer 503
		while the rest of the app keeps serving.
	</Card>
</CardGrid>
