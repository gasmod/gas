# Gas

Gas is a modular Go framework for SaaS backends. The core,
`github.com/gasmod/gas`, gives dependency injection, routing, middleware,
events and a service lifecycle. Every other capability is a module, its own
Go module, that plugs in through a provider interface the core declares, so
an app pulls in only what it uses.

## How to use this skill

- For any Gas task, read `references/gas.md` first. It is the core's
  contract: services and the container, the lifecycle, routing, handlers
  and errors, middleware and configuration. Every module builds on it.
- Then read the reference of each package the task touches, listed under
  Packages below. Each is that package's Go doc overview: its contract,
  behaviors, errors and how to test with it.
- The references leave out the API listings. For exact signatures, run
  `go doc`, which always matches the version in go.mod:
  `go doc github.com/gasmod/gas/storage.CopyObjectInput` for one
  declaration, `go doc -all github.com/gasmod/gas/storage` for all of them.
- A name in backticks, such as `storage.CopyObjectInput` or `Error`, is a
  Go identifier of the package being read or the one it names: look it up
  with `go doc`.
- Prefer what the references state over what you remember of Gas: its API
  changed between releases.

## Installation

### Requirements

- Go 1.27.3 or newer.

That is all the core needs. Some modules talk to outside services, such as
PostgreSQL, Valkey or AWS, and only need them when you use those backends.

### Add the core

In your Go module:

```sh
go get github.com/gasmod/gas
```

The core is enough for a working HTTP app. See the example on the
[home page](https://gasmod.github.io/gas/).

### Add modules

Each module is its own Go module. Add only the ones you use:

```sh
go get github.com/gasmod/gas/config
go get github.com/gasmod/gas/log
go get github.com/gasmod/gas/database
```

All modules share one version and are released together. Keep them on the
same version as the core.

### Register modules

Modules are services. You register them with the App, and its container
builds them, wires their dependencies and runs their lifecycle. This app
reads its settings from environment variables, logs through slog, and opens
a SQLite database:

```go
package main

import (
	"log"
	"net/http"

	"github.com/gasmod/gas"
	"github.com/gasmod/gas/config"
	"github.com/gasmod/gas/database"
	gaslog "github.com/gasmod/gas/log"
	_ "modernc.org/sqlite"
)

func main() {
	cfg := config.New(config.WithProvider(
		config.NewEnvProvider(config.WithEnvPrefix("APP_")),
	))
	if err := cfg.Load(); err != nil {
		log.Fatal(err)
	}

	app := gas.NewApp(
		gas.WithServiceInstance[gas.ConfigProvider](cfg),
		gas.WithSingletonService[gas.Logger](gaslog.NewSlogLogger()),
		gas.WithSingletonService[gas.DatabaseProvider](database.New()),
	)

	app.Router().Handle(nil, http.MethodGet, "/", func(ctx gas.Context) error {
		return ctx.Text(http.StatusOK, "Hello, World!")
	})

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

A few things to know:

- **Configuration needs a prefix.** The environment provider only reads
  variables that start with the prefix you give it, here `APP_`. Other
  tools' variables, such as their API keys, stay out of your config.
- **Nested keys use `__`.** `APP_DATABASE__DSN` sets the key
  `database.dsn`.
- **SQLite needs a driver.** Import `modernc.org/sqlite`, or another driver
  registered as `sqlite`. PostgreSQL and MySQL drivers come with the
  database module.
- **Modules log through a `gas.Logger`.** Register one, as above. The
  container resolves dependencies, so the order of registrations does not
  matter.

### Run it

```sh
go get modernc.org/sqlite
APP_DATABASE__DIALECT=sqlite APP_DATABASE__DSN=file:app.db go run .
```

```
INFO service initialized service=gas/database mode=sql dialect=sqlite
INFO server started environment=development addr=0.0.0.0:8080
```

`curl localhost:8080` answers `Hello, World!`.

## Packages

### core

- [`github.com/gasmod/gas`](references/gas.md): Package gas is the core of the Gas framework: a Worker that runs services with dependency injection and an event bus, and an App that adds a router and an HTTP server.

### auth

- [`github.com/gasmod/gas/auth`](references/auth.md): Package auth defines how a Gas app authenticates and authorizes HTTP requests: the Authenticator, Authorizer and PrincipalRevoker interfaces, the error contract they share, Chain to try several authenticators, and the middleware that runs them.
- [`github.com/gasmod/gas/auth/apikey`](references/auth/apikey.md): Package apikey authenticates HTTP requests by API key.
- [`github.com/gasmod/gas/auth/authtest`](references/auth/authtest.md): Package authtest holds mocks of the interfaces in package auth, for tests of code that authenticates, authorizes or revokes: MockAuthenticator, MockAuthorizer and MockRevoker.
- [`github.com/gasmod/gas/auth/jwt`](references/auth/jwt.md): Package jwt signs and verifies JSON Web Tokens with HS256 or RS256, and authenticates requests that carry one as a bearer token.
- [`github.com/gasmod/gas/auth/session`](references/auth/session.md): Package session authenticates HTTP requests by a session cookie, with the sessions kept server-side in a SQL database.
- [`github.com/gasmod/gas/auth/token`](references/auth/token.md): Package token issues single-use, time-limited tokens, for links such as a password reset, an email verification, a magic login link or an invite.

### cache

- [`github.com/gasmod/gas/cache`](references/cache.md): Package cache defines what every cache store of the module promises: the keys it accepts, how it copies values, how a TTL works, how it honors a context, its lifecycle, and the errors it returns.
- [`github.com/gasmod/gas/cache/cachetest`](references/cache/cachetest.md): Package cachetest holds a mock of gas.CacheProvider, MockCache, for tests of code that uses a cache.
- [`github.com/gasmod/gas/cache/memory`](references/cache/memory.md): Package memory is a cache held in the process's memory, as a gas.CacheProvider.
- [`github.com/gasmod/gas/cache/valkey`](references/cache/valkey.md): Package valkey is a cache on a Valkey server, as a gas.CacheProvider.

### config

- [`github.com/gasmod/gas/config`](references/config.md): Package config loads an app's configuration from providers, such as the environment, `.env` and JSON files, and AWS Secrets Manager, merges it into one tree of values, and binds that tree into structs.
- [`github.com/gasmod/gas/config/configtest`](references/config/configtest.md): Package configtest holds MockConfig, a config.ConfigProvider for tests of code that reads configuration.
- [`github.com/gasmod/gas/config/secretsmanager`](references/config/secretsmanager.md): Package secretsmanager is a config provider that loads values from AWS Secrets Manager.

### database

- [`github.com/gasmod/gas/database`](references/database.md): Package database connects a Gas app to PostgreSQL, MySQL or SQLite and provides the connection as a gas.DatabaseProvider.

### email

- [`github.com/gasmod/gas/email`](references/email.md): Package email defines what every email sender of the module promises: the messages it accepts, how it normalizes their addresses, the headers it sends, how it renders templates, how it honors a context, its lifecycle, and the errors it returns.
- [`github.com/gasmod/gas/email/emailtest`](references/email/emailtest.md): Package emailtest holds a mock of gas.EmailProvider, MockEmail, for tests of code that sends email.
- [`github.com/gasmod/gas/email/memory`](references/email/memory.md): Package memory is an email sender that sends nothing: it keeps each message in an outbox in the process's memory, for tests and local development, as a gas.EmailProvider.
- [`github.com/gasmod/gas/email/ses`](references/email/ses.md): Package ses is an email sender on Amazon SES, as a gas.EmailProvider.
